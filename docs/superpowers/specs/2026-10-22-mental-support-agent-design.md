# 中文心理支持 Agent：计划设计基线

初稿日期：2026-10-22；完成修订：2026-10-23。本文与工作计划配套，用于说明计划采用的范围和设计选择，不代表已经实现或通过临床验证。

## 用户已明确的信息

- 先做个人研究，最终希望面向用户提供心理支持。
- 希望系统根据对用户情况的判断，决定如何回答。
- 有少量 Python 基础，本次要求制作详细工作计划。

## 本计划采用的假设

- 第一阶段面向中文成年人，使用文字对话；这是规划假设，用户尚未逐项确认。
- 在有 AI 编程或熟练实现者协助的条件下，每周投入 10～12 小时，按 8 周、80～96 小时安排研究原型。若由用户独立边学边写，建议预留 12～16 周；专业人员审核和外部等待另计。
- 暂无已确认的模型服务商、专业审核人员、预算、上线地区或医疗机构合作方。
- 现有项目目录在规划时为空；本次只创建计划文档。

## 目标与范围

第一阶段交付一个可在本机演示、能运行离线回归测试、能展示判断依据的研究原型。它根据用户自述的困扰、持续时间、生活影响、需求和安全线索，选择倾听、澄清、日常支持、专业评估建议或即时安全支持。

首版支持压力、情绪低落、睡眠困扰和人际困扰。所有情况都需要考虑安全相关线索，但系统不承诺完整识别危机。涉及疑似躁狂、精神病性体验、药物或躯体病因等情况，采用经审核的专业求助策略。

临床诊断、个体化处方、独立心理治疗、未成年人服务、语音视频、模型微调、付费服务及公开上线不属于这 8 周的交付范围。若后续研究诊断辅助功能，需要医疗机构合作与另行验证。在中国大陆，精神障碍诊断由精神科执业医师作出，依据见[《精神卫生法》第二十九条](https://www.nhc.gov.cn/fzs/c100048/201808/5d03e37b37c944b08d701a0b5722160a.shtml)。

## 比较过的实现方式

| 方式 | 优点 | 成本与限制 | 本计划选择 |
|---|---|---|---|
| Dify 可视化工作流 | 初期搭建快，能看到分支与检索过程 | 深度定制、测试与数据流仍需理解和实现 | 可作为不想写代码时的替代 |
| Python + 现成模型 API + 明确流程 | 便于学习、调试、测试，能逐步控制规则 | 需要学习少量接口调用和数据校验 | 推荐默认方案，尚非用户单独确认的技术决定 |
| 自行部署并微调模型 | 后期可能满足特定部署需求 | 数据授权、算力、训练和评测负担较大 | 首版暂不采用 |

## 架构

本地界面 → 消息与会话管理 → 结构化状态提取 → 规则选择回应动作 → 检索授权知识卡 → 生成回复 → 输出检查 → 展示回复。

模型用于语言理解和组织表达；程序承担字段校验、规则优先级、调用限制、数据隔离和失败处理。每轮重新评估必要上下文；模型建议的动作不能绕过规则。

风险识别发生在知识检索和普通回复之前，不依赖检索是否命中。即时安全支持流程不等待普通知识检索。没有实际人工团队或成功接入记录时，不能声称已转接医生、通知家属或发起救援。

## 全局约束

- 运行环境：Windows，本地开发；目标 Python 3.12，依赖在首次兼容性验证后锁定具体版本。
- 技术栈：Python、Pydantic 2、Streamlit、pytest，以及最终选定服务商的接口适配器；首版不依赖复杂 Agent 框架或向量数据库。
- 面向对象：中文成年人；首版真实数据留存默认关闭。
- 对话数据：原型只保存在当前会话内存中；清除会话后不得继续用于上下文；供应商侧留存须另行核查，不能承诺随本地清除而删除。
- 日志：不记录用户原文、模型完整回复、API 密钥或用户身份；测试报告只允许包含虚构案例。
- 数据使用：授权状态不明确的内容不得进入可分发的知识库、训练材料或产品；用户对话不得默认进入训练集。
- 判断：允许未知、矛盾、多种困扰并存；没有识别到线索不等于排除风险。
- 回应动作：listen、clarify、support、refer、urgent_support。
- 量表：PHQ-9/GAD-7 等不是首版必需功能；后续使用需核对版本、授权、适用人群，并由程序按正式规则计分。
- 安全：不用量表分数或低中高分层预测未来自杀、自伤；不把模型自报置信度当作医学概率。
- 检索：先使用知识卡的人工标签和关键词；每次最多返回 3 张，空结果保留为空；未授权、未审核或不适用于当前人群的卡片不可用于真实用户回复。
- 调用控制：每轮最多 4 次外部模型请求，失败请求计入；单次超时 20 秒、整轮截止 45 秒；生成内容在检查前不向用户流式输出。
- 故障：模型、校验或知识库故障有明确状态与备用回复；不能把失败解释为用户安全。
- 上下文：超出模型上下文或预算时明确返回受限状态，不静默删除尚未澄清的安全线索；所有证据保持消息引用。
- 原型与真实用户试用之间设置独立验收；8 周结束不自动启动真实用户试用。

量表与危机判断边界依据：[NICE 自伤指南 1.6](https://www.nice.org.uk/guidance/ng225/chapter/recommendations#risk-assessment-tools-and-scales)。医疗健康数据在中国大陆属于敏感个人信息，处理规则和跨境问题应按实际数据流核查，依据：[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

## 数据与评测规模

- 40 张知识卡：作为研究原型的起步工作量，不代表医学覆盖充分；知识、授权和专业审核分别记录。
- 120 个虚构场景：80 个开发场景、40 个保留场景；按场景家族分组，改写、同一虚构人物、多轮对话不得跨集合。
- 上述数量是工程规划值，不是临床样本量；专业人员的审核、真实用户验证另行安排。
- 开发者不使用保留集调提示词。若保留集失败后用于改进，相应案例转入回归集，并重新准备独立保留案例。
- 所有确定性规则测试通过；严重问题没有未处理项；人工评审报告明确样本与限制。上述条件仍不代表临床有效或适合公开上线。
- 模拟接口仅证明流程和规则能运行；真实模型调用、保留集评测和报告完成后才能称为模型接入版研究原型。没有 API 时交付工程框架，并明确记录尚未完成的模型验证。

## 后续真实用户试用需要另行完成的设计

专业负责人、目标用户与招募、伦理和合规适用性、知情同意、访问控制、数据删除、供应商处理条款、实际可执行的求助流程、异常事件与暂停机制。没有专业审核或无法执行求助流程时，保持虚构案例演示。

## 尚需在执行时作出的决定

第 1 周确定模型服务商、模型版本和预算封顶；第 2 周明确知识资料的使用授权和专业审核安排；真实用户试用前确定部署地区、数据流、服务责任与适用规则。未确认这些条件，不使用真实用户数据进行模型服务商测试。
