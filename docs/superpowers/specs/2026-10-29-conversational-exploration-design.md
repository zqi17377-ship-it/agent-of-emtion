# 多版本问卷与对话探索设计建议稿

日期：2026-10-29。状态：制作方案，自动探索和新问卷版本尚未接入应用。用户另外授权用现有 DeepSeek API 优化提示词；独立候选提示词的合成案例试测不代表本方案已经上线。

## 目标与当前基础

用户希望在同一测量主题下选择不同题数的工具，同时在自然对话达到一定量后，由 agent 根据用户自己的回答观察性格、MBTI 风格偏好及亲密/人际关系中的依恋倾向。目的在于减少填表负担，并让观察随新信息修正。

当前应用已有七类工具。MBTI 风格分析由用户单独同意后主动点击触发；六份问卷在本机计分。`ExplorationState` 已隔离每段对话的结果、答案和自我确认，失败不覆盖旧观察。当前聊天上下文有 18,000 字符边界，性格分析有 16,000 字符边界，不能假定长对话可以无限发送。当前仍是成年人虚构案例的非商业研究原型。

本方案补充三项：多版本量表目录；首次授权后按对话量触发的观察流程；由原话、关系情境、反例及本人修正组成的观察报告。

## 可选路线与建议

| 路线 | 做法 | 取舍 |
| --- | --- | --- |
| 只用自然聊天推断 | 到达轮数后直接输出性格/关系倾向 | 负担低，但信息覆盖受聊天主题影响大，易把当前处境当作长期特征 |
| 聊天线索＋少量中性补问＋可选问卷（建议） | 到量后检查证据，缺少什么再询问，保留未知，可用正式版本问卷另行核对 | 更贴合现有代码，能解释依据和矛盾；需要管理证据与来源 |
| 问卷逐题聊天化 | 按原题与原选项逐题发问，本机计分 | 容易明确哪些题已答；仍然是填写问卷，逐轮口头呈现不自动继承原施测方式的效度 |

以下按第二条路线提出默认值，尚不把该选择写成用户已经批准。第一版不做在线自我修改模型、权重训练、跨会话隐性画像或临床诊断。问卷分数、对话观察和用户本人确认分别保存，互不冒充。

## 一、不同题数的目录

目录先按测量主题组织，再显示实际工具名称、版本、题数、预计用时、语言、许可与验证状态。题数不是量表身份；增加题数也不自动提高对本人的判断准确度。

| 主题 | 已核实的题数方案 | 第一版安排 |
| --- | --- | --- |
| 大五人格 | TIPI 10；Mini-IPIP 20；IPIP Big-Five Factor Markers 50/100 | 保留10/20，优先加50，100后置。TIPI是另一工具，不能标成IPIP的10题版；负性情绪与情绪稳定性方向要分别标注 |
| BFI-2 大五系列（备选） | BFI-2-XS 15；BFI-2-S 30；BFI-2 60 | 这是正式同系列长短版；非商业范围、中文短版题文与适用性核实后再启用。短版不输出不受支持的个体侧面报告 |
| 依恋 | ECR-RS每段关系9；ECR-S 12；ECR-R 36 | 9/36优先研究，12先列候选。ECR-S来自原ECR，不是随意截短ECR-R；ECR-RS不是ECR-R简单短版。现有原创12题保留为独立练习 |
| 生活满意度 | SWLS-3、SWLS-5 | 已有5题；核对3题版本中文来源/许可后加入。3题用规定题目，不能任意挑3题。原始总分3—21与5—35不可直接比较 |
| 自尊 | 当前已核实RSES 10 | 保持10；不为了显示短/中/长而自行编出标准5题版 |
| MBTI风格 | 现有原创8题与自由对话 | 保持原创标识；不编造“官方16/32题版”或把聊天转换成官方MBTI分数 |

每个版本独立保存 `construct_id, instrument_id, version_id, language_version, item_count, scoring_key_version, permission_scope, source_url, validation_population`。完整版本身份进入答案存储键、结果结构、控件键和导出，不能只用旧test_id或题号；切换共享题号的版本不得继承答案。同一主题的不同工具不直接合并原始分数。自译、转载译文、经过发表验证的中文版本是不同状态，不能混用标签。

依恋以焦虑、回避两维和具体关系为主。没有天然正确的四类型分界；若展示安全/焦虑/回避等解释性示意，必须注明其规则和局限，不能称稳定类型或诊断。

## 二、对话中如何探索

建议一次明确授权，包含允许分析的主题、会话范围、DeepSeek数据流向、额外调用与关闭入口。默认关闭。选项可分为“只在我点击时分析”“达到门槛后自动整理”“暂停”；用户的授权不是训练数据授权。先不跨会话合并。

建议初始调度参数如下，全部是待验证的产品参数，**不是科学上聊够这些轮就能测准的阈值**：

- 一轮按一条成功接收的用户消息计算，不把助手回答计入。明显重复、空白、仅表情/附和等不累积有效内容；不能仅靠长度证明消息有心理信息。
- 到20条候选用户消息且累计至少1,000个非空白字符后，启动一次证据检查。少于门槛也允许用户主动查看“已有线索”，缺失项仍未知。
- 每个明确方向初步要求至少3条不同用户消息、至少3个不同事件、覆盖至少2类情境。拆分一件事、复述同一句话不重复加权。这只是保守工程门槛，不是效度证明；事件与情境语义仍可能识别错误。
- 依恋门槛按关系分别计算，伴侣、父母/家人、朋友不共用证据数量。需要明确本人反应、关系对象和时间情境；没有这类内容就不输出依恋方向。
- 首次整理后至少新增10条候选用户消息才自动复查；每段对话最多3次自动整理。关闭自动分析、上下文未变化、费用预算不足、当前需优先即时支持时不启动。
- 每次整理最多2个请求（初次＋仅用于结构修复的一次），共享40秒期限；初步提案总计每会话最多6次额外请求。输出实际请求/用量，不承诺超时后供应商不会计费。
- 手动、自动、结构修复共享这6次请求额度，提交时原子预留；已发送的失败/超时请求不返还额度，未发送的预留可释放。不能通过手动按钮绕过上限，也不能把显示错误当作没有花费。
- 证据不足时，记录“信息不足”，由用户选择是否补问；每次最多2个中性问题，可以跳过。达到轮数不强制弹窗，也不在倾诉过程中插入测试结论。

流程：正常聊天 → 同意及调度检查 → 固定原话快照 → 提取本人行为/情境/时间/关系 → 校验引用与来源 → 逐维检查覆盖和反例 → 显示可选报告或中性补问 → 用户修正 → 下次有新证据再更新。

## 三、需要提取的内容与结果表达

内部记录包含 `observation_id, domain, dimension, direction, subject, scope, relation_context, relation_id, event_id, context_kind, evidence, counter_evidence, source_message_ids, created_at, prompt_version, model_id, snapshot_revision, observation_revision`。`evidence`保留消息ID和连续原文，并逐项关联事件、情境和会话内匿名关系对象ID；所有摘要都能回到仍被保留的原话。

- `domain`：MBTI风格、大五宽维、依恋。不同框架独立处理，不用大五自动换算MBTI。
- `subject`：本人、他人、引述、假设或不明；只有明确本人的经历才候选进入本人观察。
- `scope`：通常习惯、当前状态、不明。一次失恋、今天睡不好或当下退缩不构成长久偏好。
- `relation_context`：伴侣、朋友、具体家人或不明。避免姓名与可识别对象；同属“朋友”也不自动合并两个不同人的事件。
- `relation_id`：例如本会话的friend_1/friend_2，只作本机匿名区分，不记录真实姓名。关系不明时不能凑齐某段关系的3事件门槛；不要求用户透露身份。
- `direction`：偏向一端、两向并存、未知；依恋为有相关线索/反例/不足。首版不输出量表分数、置信概率、常模百分位。

资料中的“我朋友说他是INFP”、粘贴的角色设定、助手的问题、代替别人说的话，不能作为用户本人的偏好证据。用户自报类型也不能反过来证明行为。重复描述、否定、引用和用户后续纠正应专门处理。字面引用校验只能证明文字确实出现过，不能证明心理解释正确。

示例展示（虚构）：

> 社交恢复：目前有偏向独处恢复的线索，来自3个不同事件。
>
> 做决定时的偏好：信息不足，暂不判断。
>
> 伴侣关系：等待回应时反复担心关系的例子较多；也有能沟通需要的不同线索。
>
> 朋友关系：尚无足够情境，不沿用伴侣关系的观察。
>
> 可操作：查看原话／补充例子／这不是我的通常情况／只谈这次感受／删除这条观察。

补问示例：“这是这次事件的反应，还是在其他关系或场合也常发生？”“对方没有马上回复时，你通常会怎样理解，后来会怎么做？”避免“你是不是焦虑型”这类引导确认标签的问题。

报告展示当前覆盖、反例与缺失；不显示“MBTI准确率87%”等未经校准数值。只有用户明确确认的偏好可用于调整沟通形式，例如先给梗概或分步骤；不以推测的人格改变医疗判断、危机支持或专业求助门槛。

## 四、在当前项目中如何落地

保持Python、Streamlit、Pydantic、DeepSeek和现有本机计分。建议新增 `survey_registry.py`（版本目录）、`conversation_observation.py`（提取与结构校验）、`observation_scheduler.py`（门槛/去重/上限）、`observation_jobs.py`（本机任务）及对应测试；扩展现有 `ExplorationState` 与探索页面。此处为建议的文件名，未创建这些产品模块。

聊天响应先完成，再提交观察任务。后台线程只处理不可变的用户文字快照，不从线程读写Streamlit session_state；主线程用片段定时检查结果。每段对话最多一个在途任务，不持久运行不受控循环。完成时核对会话ID、会话代际、同意版本、观察修订号与快照；清空/删除/撤回同意后返回的旧任务丢弃。单条删除、标为当前状态或不认同同样递增观察修订号，旧任务不得恢复这些观察；针对旧证据与维度的修正约束进入后续快照，用户可显式重新允许。对话有新内容则标注结果基于哪个时间点，不静默覆盖新结果。

授权主题进入快照、提示词与允许输出schema；本机拒收越界主题结果。“只同意MBTI”时不得请求全部主题后仅隐藏依恋展示。额外的数据范围选择限制实际发送的消息，不以展示过滤代替数据流向控制。

分析预算与聊天预算分开显示，但都计入页面可见的总调用量。观察超时或失败不能挡住已经生成的支持回复，也不能将旧观察装成新结果。离线模式只展示真实本机问卷与进度，不伪造模型性格结论。

长对话需要单独处理：按有原文依据的事件与窗口管理输入，先在当前18,000/16,000字符边界之前提示；纯文字摘要不能替代证据。第一版遇到先达到字符上限但未满20条时，提供主动查看现有线索/导出/另开会话的明确提示，不强行等待门槛或偷偷删历史；报告注明实际分析范围，超限不发送。若要压缩聊天上下文或支持持续长聊，另行验证支持流程对未解决安全信息的保留，不能把人格功能的截取规则直接用于临床支持上下文。

记录仍限当前会话内存，按需导出；不默认写入数据库，不把真实对话追加到评测或训练集。删除本地数据不等于删除供应商已收到的内容。以后要跨会话记忆，作为独立功能另做可见、可删除和可撤回的设计。

## 五、提示词优化与评估

当前选择是优化既有DeepSeek提示词与效果，不是更新模型权重。流程为：固定案例和预期 → 运行基线 → 改候选提示词 → 同一保留集比较 → 人工核对错误 → 版本化发布。生成数据只能辅助工程验证，模型自行给出的“正确标签”不能作为真实心理学标准答案。

首轮可用3次以内真实请求检查独立候选提示词，结果如实写入报告；小样本不能证明效果提升。后续建议先构建100个有人工可核对标注的虚构案例，60个开发、20个验证、20个冻结测试；按同一人物/事件/模板家族分组，避免变体跨集合泄漏。此数量是工程起点，不是足够证明测量效度的样本量。

本轮独立候选v1用两条消息测试基础引用协议，没有实现本方案的20条调度与3事件门槛，不能直接作为上线版本。首次3次合成请求中2组满足预设检查，1组未输出预期的大五条目；保持原报告，不据此宣称准确率或提升。该条目的强制输出预期还需人工审查，不能因为EI偏向独处就强制补出大五外向性。候选及评测入口见 `prompts/conversation_observation.md`、`scripts/eval_conversation_observation.py`；live报告与dry-run报告分开保存。

案例覆盖：明确习惯、当前情绪、关系切换、反例、转述他人、角色扮演、仅自报类型、提示注入、否定和纠正、重复拆消息、短回复、不相关长文、模型超时及上下文边界。每个需要方向标签的案例由独立人工审阅，分歧可保留未知；人工对文字的标注也不等于本人真实人格。

主要工程指标为：结构通过率、无效引用被拒率、已知转述/状态材料的误归因率、关系串用率、反例保留率、证据不足仍强判的比例、撤回后的返回丢弃率、延迟和token用量。关键合成反例要求零错误才进入下一轮，这是有限测试集验收，不是对未知输入的保证。

后续如开展真实人群研究，需要独立同意、适用语言的问卷参照及专业研究设计，比较维度相关、一致性、重测与群体差异，按参与者划分数据。问卷自报是参照而非绝对真值；大五结果不能替代MBTI或依恋的分别验证。研究表明语言推断有潜力，也存在明显的语境和效度限制；一次接通或稳定重复不证明准确。
