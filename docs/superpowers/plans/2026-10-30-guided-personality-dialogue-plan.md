# 对话探索改进执行计划

1. 并行审计聊天链路与观察链路，复现unknown/伪反例/主体冲突，并核实DeepSeek当前API参数。
2. 访谈模块负责只读上下文、计划、原文定位的回答类型及成功后推进；接入现有assessment/response/check调用，不增加独立分类请求。
3. 观察模块按原门槛派生分层覆盖及初步方向，修复重复反例，支持可信虚构案例主体；使用真实运行提示词。
4. 后台网关增加独立purpose与请求上限，默认聊天行为兼容；root接入UI、关系范围、快照身份、进度与分层报告/导出。
5. 对有意义的行为变更先运行失败回归再实现；并行代理分别拥有聊天模块、分析模块、网关模块，root拥有调度/界面/整体验证，避免交叉写入。
6. 全套回归和check_data后，以单轮最多14个真实API请求检查3轮固定虚构访谈及分层报告案例。首次发现复问与超时后作有限调优，完整记录累计27请求；核对实际输出、原话引用和请求预算，不把软件或少量API检查当成心理测量有效性。
7. 独立审查、实际页面验收、文档更新与仅源码GitHub提交；保持现有用户对话，不使用其材料做API评测。
